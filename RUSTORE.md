# Публикация PIP в RuStore (TWA)

PIP — это PWA на https://pipup.ru, упакованная в **TWA** (Trusted Web Activity):
нативная Android-обёртка, которая открывает сайт в полноэкранном режиме без
адресной строки. Для этого нужен валидный `assetlinks.json` (Digital Asset Links).

Канонический идентификатор пакета: **`ru.pipup.twa`** (см. `twa/twa-manifest.json`,
`public/manifest.json`, эндпоинт assetlinks). Если у основателя реальный AAB собран
под другой id (напр. `ru.pipup.app`) — поменяй `packageId` в `twa/twa-manifest.json`,
переменную `TWA_PACKAGE_NAME` на сервере и `related_applications` в манифесте, затем
пересобери.

---

## 0. Предусловия

1. **Аккаунт разработчика RuStore.** Нужен подтверждённый аккаунт: ИП, юрлицо или
   самозанятый (верификация через Госуслуги/ЭП). https://www.rustore.ru/help/developers/
   Без него загрузить приложение нельзя — это первый шаг, делается заранее.
2. **JDK 17** и **Android SDK** (или просто Bubblewrap CLI — он умеет доставить JDK/SDK
   сам при `bubblewrap doctor`).
3. **Node 18+** (для Bubblewrap CLI).

---

## 1. Сборка AAB через Bubblewrap

```bash
npm i -g @bubblewrap/cli

# рабочая папка сборки (вне репозитория или в twa/)
mkdir -p ~/pip-twa && cd ~/pip-twa
cp "<repo>/twa/twa-manifest.json" ./twa-manifest.json

# первый раз — сгенерировать android-проект из манифеста
bubblewrap init --manifest https://pipup.ru/manifest.json
#   на вопросы отвечай значениями из twa-manifest.json;
#   Application ID = ru.pipup.twa, host = pipup.ru.
#   Bubblewrap предложит СОЗДАТЬ keystore (android.keystore) — согласись и
#   ОБЯЗАТЕЛЬНО сохрани файл + пароли (это ключ подписи, потеряешь — не обновишь приложение).

# собрать релиз (AAB + APK)
bubblewrap build
#   попросит пароль keystore. На выходе: app-release-bundle.aab (для RuStore) и
#   app-release-signed.apk, плюс assetlinks.json с правильным отпечатком.
```

> Если уже есть keystore основателя (`signing.keystore`) — положи его как
> `android.keystore` и пропиши `alias` в `twa-manifest.json`, тогда `bubblewrap build`
> подпишет тем же ключом (тот же отпечаток → ничего менять в assetlinks не нужно).

### Альтернатива: PWABuilder (GUI)
https://www.pwabuilder.com → ввести `https://pipup.ru` → Package For Stores → Android →
выбрать «Other / TWA», Application ID = `ru.pipup.twa`. Скачать пакет, там будет
`signing.keystore` + инструкция + `assetlinks.json`.

## 2. Отпечаток ключа → assetlinks (КРИТИЧНО)

`assetlinks.json` должен содержать **SHA-256 отпечаток ключа, которым реально
подписан установленный APK**. Иначе Android покажет адресную строку, а TWA-проверка
не пройдёт.

Узнать отпечаток из keystore:
```bash
keytool -list -v -keystore android.keystore -alias pip | grep -i SHA-256
# Формат: AA:BB:CC:...:ZZ (64 hex через двоеточие)
```

Эндпоинт assetlinks читает значения из ENV (можно обновить БЕЗ передеплоя кода):
на сервере в `/opt/pip-app/.env.local` добавь/поменяй:
```
TWA_PACKAGE_NAME=ru.pipup.twa
TWA_SHA256_FINGERPRINTS=<сюда SHA-256 из keytool>
```
затем перезапусти: `systemctl restart pip-app`.

Несколько отпечатков — через запятую (нужно, если включишь **сервис подписи RuStore**:
RuStore пере-подписывает своим ключом → добавь его SHA-256 из консоли RuStore вторым
значением).

Текущее значение по умолчанию (фолбэк в коде): `50:C4:4F:2C:EE:19:46:E9:8A:7E:16:83:CD:15:4D:ED:EA:10:C6:FE:DC:E4:50:D7:6F:AE:33:23:47:1A:6E:41`
— **проверь, что оно совпадает с твоим keystore**; если нет — задай через ENV.

### Проверка
```bash
curl -s https://pipup.ru/.well-known/assetlinks.json
```
Должны совпасть: `package_name` = id из AAB, `sha256_cert_fingerprints` = отпечаток ключа.
Онлайн-валидатор: https://developers.google.com/digital-asset-links/tools/generator

После установки TWA на телефон — приложение должно открываться **без адресной строки**.

| Поле | Значение |
|------|----------|
| **Название** | PIP — копилка хороших привычек |
| **Короткое описание** (до 80) | Дети выполняют задания, копят PIP-монеты и меняют на награды |
| **Категория** | Образ жизни / Семья (или Образование) |
| **Email поддержки** | saymien1@gmail.com |
| **Политика конфиденциальности** | https://pipup.ru/privacy |
| **Условия использования** | https://pipup.ru/terms |
| **Сайт** | https://pipup.ru |
| **Возрастная категория** | 6+ (нет насилия, рекламы, чатов, пользовательского контента вовне; см. ниже) |

**Полное описание:**
```
PIP — семейное приложение, которое превращает домашние дела и хорошие привычки в игру.

Как это работает:
• Родитель создаёт задания (убрать комнату, сделать уроки, помочь по дому) и назначает за них PIP-монеты.
• Ребёнок выполняет задания и отмечает их в своём простом и понятном экране — вход по PIN, без регистрации.
• За выполненное — монеты на счёт. Их можно копить и обменивать на согласованные с родителем награды.
• Стрики и достижения мотивируют не бросать.

Почему PIP:
• Без реальных денег и без угроз — только позитивная мотивация.
• Прозрачно для родителя: подтверждение заданий, история, баланс, цель-копилка.
• Несколько родителей в одной семье.
• Напоминания, чтобы не забыть про задания.

PIP помогает детям 6–16 лет учиться ответственности и доводить дела до конца, а
родителям — меньше уговаривать и больше радоваться результату.
```

**Что нового (для первой версии):**
```
Первая версия PIP в RuStore: задания, PIP-монеты, награды, цель-копилка, достижения,
вход ребёнка по PIN, напоминания и несколько родителей в семье.
```

## 5. Возрастной рейтинг (анкета RuStore) — ответы

- Насилие / жестокость: **нет**
- Сцены сексуального характера: **нет**
- Ненормативная лексика: **нет**
- Азартные игры / ставки: **нет**
- Реклама и встроенные покупки: **нет** (на момент первой версии)
- Сбор геолокации: **нет**
- Пользовательское общение / UGC наружу: **нет** (данные только внутри семьи)
- Реальные деньги: **нет** (PIP-монеты — внутренняя условная валюта)

Итог: ожидаемая категория **6+** (можно 0+, если анкета RuStore позволит).

## 7. Если меняется идентификатор пакета на `ru.pipup.app`
1. `twa/twa-manifest.json` → `"packageId": "ru.pipup.app"`.
2. `public/manifest.json` → `related_applications.id` и `url` → `ru.pipup.app`.
3. Сервер: `TWA_PACKAGE_NAME=ru.pipup.app` + `systemctl restart pip-app`.
4. Пересобрать AAB (новый id ⇒ при первой публикации это новое приложение).
