## 0. Ключевые факты, определяющие стратегию (проверено, июль 2026)

| Факт | Следствие для PIP |
|---|---|
| **4.2.2** буквально запрещает «web clippings» | Обёртка вокруг сайта, как наш Android TWA, не пройдёт. Нужна нативная ценность |
| **4.7 к нам не применяется** | Преамбула 4.7 адресована хостам сторонних mini-apps; 4.7.4 требует «индекс софта с universal links» — для одноцелевого PIP бессмыслица |
| **Статический бандл не требуется** ни одним гайдлайном | 4.2 оценивает нативную ценность, а НЕ место хранения бандла. Ревьюер не вскрывает .ipa. Полный SPA-рефактор (2–3 мес) почти не снижает риск 4.2 |
| **PWABuilder iOS мёртв** (архив 11.09.2025) | Этот путь исключён |
| **Платежи Apple в РФ отключены с 01.04.2026** | На российском юрлице iOS-приложение может быть **только бесплатным**. IAP/подписки нереализуемы: Paid Apps Agreement для РФ недоступно, а россияне не могут платить. Монетизация потребует зарубежного юрлица |
| **Kids Category не подходит** | Возрастные полосы кончаются на 11 годах, у PIP 6–16. Идём как **семейное приложение, рейтинг 4+, обычная категория**. Но **5.1.4 применяется всё равно** |

**Вывод:** iOS сейчас = охват + фича Screen Time, но **не деньги**.

## 1. Нативная ценность = ответ на 4.2 (Screen Time)

Фича: ребёнок заработал монеты → родитель тратит их на разблокировку N минут экранного времени. **В вебе невозможна** — это и есть железный ответ ревьюеру «почему это не сайт».

**Архитектура (проверено):**
- `.child`-авторизация требует Family Sharing → **нам не подходит** (ребёнок часто не в круге родителя).
- **`.individual` (iOS 16+) работает БЕЗ Family Sharing**: нативное PIP-приложение на устройстве ребёнка → `.individual` авторизация → `FamilyActivityPicker` на этом же устройстве → щиты ставит/снимает локальный код. «Удалённость» даёт наш бэкенд + пуш.
- **Прецеденты в App Store 2026:** `Earn Screen Time: Kids Chores`, `Chirp`, **`Applowance`** (Family Sharing не нужен, ребёнок входит 6-значным кодом со своего устройства, родитель аппрувит из пуша — буквально наш `/join/[childId]` + PIN). Значит Apple такой кейс одобряет.
- **Приватность:** данные Screen Time на свой сервер отправлять НЕЛЬЗЯ и технически невозможно (opaque-токены, у extensions нет сети). Нам и не нужно — сервер знает только «выдано N минут».
- **Цена:** требует нативного детского приложения + APNs.

**Entitlement `com.apple.developer.family-controls`:**
- Только по заявке: https://developer.apple.com/contact/request/family-controls-distribution
- Подаёт **только Account Holder**. По bundle ID **и отдельно на каждое Screen Time extension** (забыть про extensions — топ-причина отказа).
- Приложение НЕ обязано быть преимущественно родительским контролем, но обоснование должно быть конкретным: вести с флоу по шагам, а не «приложение мотивации детей».
- Срок: от 4 дней до недель; для РФ-юрлица закладывать **1–2 месяца**.
- Разработка идёт параллельно на development-entitlement (одобрение не нужно).

## 3. Заметки для App Review (черновик)

> PIP — семейное приложение: родитель ставит ребёнку бытовые задания, ребёнок выполняет,
> получает виртуальные PIP-монеты и обменивает их на награды, о которых семья договорилась.
> Реальных денег и покупок в приложении нет — монеты существуют только внутри семьи.
>
> **Как войти:**
> Родитель: `<email>` / `<пароль>`
> Ребёнок (важно — у детей НЕТ регистрации): на экране входа выберите «Ребёнок»,
> откройте ссылку `<join-ссылка>` и введите PIN `<4 цифры>`.
> Без этого детская часть приложения недоступна.
>
> **Детские данные:** имя (может быть вымышленным), год рождения (необязателен),
> аватар и фото-подтверждения заданий. Собираются только после явного согласия родителя,
> которое фиксируется на сервере. Рекламы, сторонних аналитических SDK, геолокации,
> внешнего общения и покупок нет. Удаление аккаунта и всех данных — внутри приложения:
> Профиль → Удалить аккаунт.

## 4. Что делать по порядку

**Сейчас (бесплатно, долгий лид-тайм, только Account Holder):**
1. Подать заявку на Family Controls entitlement.
2. Забронировать 1-on-1 с App Review (`developer.apple.com/events`) — узкий вопрос: проходит ли 4.2 одноцелевое семейное приложение со своим контентом в нативной оболочке + нативные Screen Time/пуш/камера; применяется ли 4.7 к first-party контенту. **Ответ определяет архитектуру** — до него не писать код оболочки.

**Параллельно (нужно при любой архитектуре):**
3. Применить миграции 025/026, задеплоить, прогнать rollback-тест удаления.
4. Завести демо-аккаунт для ревьюера + вписать доступы в Review Notes.
5. Определиться с рабочим контактным адресом (см. «Открытые вопросы»).

**После ответа App Review:**
6. Нативная оболочка + Screen Time (`.individual`) + APNs. Оценка **3–5 недель**.
7. Скриншоты/метаданные → TestFlight → подача. Ревью 2–5 дней, закладывать 1–2 итерации реджекта.

## 5. Открытые вопросы

- **Контактный адрес.** В продукте три разных: `hi@pipup.ru` (8 мест), `saymien1@gmail.com` (4), `hello@pipup.ru` (2). MX → `mx1.timeweb.ru`. Существуют ли ящики `hi@`/`hello@` — не проверено. **Мёртвый адрес в карточке = реджект.** Выбрать один рабочий и унифицировать.
- **Монетизация.** На российском юрлице на iOS невозможна. Если подписка в планах всерьёз — нужен зарубежный контур, это отдельный проект.
- **Скриншоты.** В `CLAUDE.md` помечены как «программные заглушки», в RUSTORE.md — как финальные. Сверить с текущим UI: расхождение скриншотов с приложением — отдельная причина реджекта.
